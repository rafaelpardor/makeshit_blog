# Golang

Rule of thumb for Concurrency Pattern selection In Go: 
-> when you need to process data in stages, USE Pipeline 
-> when you need to speed up a slow stage, USE Fan-In/Fan-Out 
-> when you need to Limit Concurrent workers, USE Worker Pool or Semaphore 
-> when you need to handle flaky services, USE Circuit Breaker 
-> when you need to Cancel on done channel, USE Or-Done channel 
-> when you need to Run tasks and get first error, USE Error Group 
-> when you need to Add timeouts, USE Context 
-> when you need to Flatten nested channels, USE Bridge channel 
-> when you need to Duplicate a stream, USE Tee channel 
-> when you need to broadcast events, USE Pub/Sub
