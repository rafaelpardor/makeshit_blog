Top 10 observability mistakes I keep seeing: 
1) No correlation IDs, so logs, traces, and requests never line up 
2) Logging only errors, then wondering why every incident starts with guesswork 
3) No RED/USE metrics (rate, errors, duration / utilization, saturation, errors) on critical paths 
4) Cardinality bombs: userId in labels/tags, unbounded dimensions, exploding your bill and queries 
5) Sampling done wrong: dropping the slow/failed traces that you actually need 
6) Missing SLOs and error budgets, so alerts are based on vibes and CPU graphs 
7) Alerting on symptoms too late (500s) instead of leading indicators (queue depth, p95 latency, timeouts) 
8) Dashboards with averages only; p50 looks fine while p99 is on fire 
9) Logs with no structure or context (no request path, tenant, build sha, region, dependency timings) 
10) No ownership for telemetry: nobody reviews instrumentation like code, so it rots and lies over time
