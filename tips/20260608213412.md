Want to operate like a senior/staff engineer? Stop optimizing for tickets. Optimize for outcomes and time. 
1. Ownership: pick up the messy thing no one owns. Write the doc, set SLOs, add alerts, define rollback. Close the loop after the incident. 
2. Ambiguity: turn vague asks into a 1-pager with options, risks, and a decision. Ask for constraints: latency, cost, compliance, oncall load. 
3. Technical judgment: choose boring when it’s enough. Know when to pay complexity (caching, async, sharding) and when a better index + timeout fixes it. 
4. Communication: default to written updates. Weekly status with what changed, what’s stuck, and the next decision needed. 
5. Make others faster: build guardrails. CI that catches footguns, templates, runbooks, local dev scripts, and one dashboard that answers why is prod slow
